# changhong-newtek-ac
Протокол обмена между блоком IDU &lt;-> WIFI. Интеграция в ESPHome и HomeAssistant

Локальный компонент (External Component) для **ESPHome** и **Home Assistant**, позволяющий управлять сплит-системами OEM-производства **Changhong** по внутреннему протоколу UART без использования облака Tuya / Smart Life и штатного Wi-Fi донгла.

Протестировано на кондиционере **Newtek 65C12** (база Changhong) с использованием микроконтроллера **ESP8266**. Также подходит для совместимых моделей брендов **Changhong, DEXP, Бирюса, Rovex** и других OEM-клонов с 22-байтным протоколом (`0xAA 0x14...`).

## Возможности
* **Полное управление климатом:** Питание (`Off`), режимы `Auto` (`Heat/Cool`), `Cool`, `Heat`, `Dry`, `Fan Only`.
* **Скорости вентилятора:** `Auto`, `Low`, `Medium`, `High`.
* **Управление жалюзи (Swing):** Вертикальные, горизонтальные и оба привода одновременно.
* **Пресеты (Presets):**
  * `Boost` — режим **Turbo** (максимальная мощность).
  * `Sleep` — ночной режим **Сон**.
  * `Comfort` — тихий режим **Quiet / Silent**.
* **Датчик комнатной температуры:** Чтение актуальной температуры воздуха с внутреннего датчика кондиционера (`current_temperature`).
* **Управление подсветкой дисплея:** Отдельный переключатель (`switch`) для включения и выключения индикации на внутреннем блоке без сброса текущих настроек.
* **Диагностика:** Сенсор кода ошибки самодиагностики кондиционера (`0` — норма, `2` — `F6`, `27` — `E1` и т.д.).
* **Защита от блокировки:** Автоматическая генерация случайного `Session ID` при каждом старте ESP.

## ⚠️ Важно: Активация UART-порта
На многих платах Changhong / Newtek порт UART для Wi-Fi модуля по умолчанию **отключён** (на линии тишина). 
Чтобы разбудить порт, включите кондиционер в сеть и **нажмите кнопку `Display` (или `Light` / `LED`) на родном ИК-пульте 6 раз подряд** (активация режима сопряжения Wi-Fi). После этого плата начнёт обмениваться пакетами по UART.

## Подключение (Hardware)
* **Параметры UART:** `9600` бод, `8N1`, без контроля чётности.
* **Уровни сигналов:** Логика ESP8266/ESP32 работает на **3.3 В**. Если на разъёме платы кондиционера логика **5 В**, используйте преобразователь уровней или резистивный делитель на линию `RX` микроконтроллера.
* Для ESP8266 рекомендуется использовать аппаратный `UART0` (`GPIO1` — TX, `GPIO3` — RX), отключив вывод логов в Serial (`baud_rate: 0`).

| Плата кондиционера | ESP8266 |
| :--- | :--- |
| `5V` (через понижающий DC-DC 3.3V) | `3V3` / `VIN` |
| `GND` | `GND` |
| `TX` | `GPIO3` (RX) |
| `RX` | `GPIO1` (TX) |

## Установка
1. Скопируйте папку `components/changhong_ac` в директорию `/config/esphome/components/` вашего сервера Home Assistant (или подключите репозиторий напрямую через `external_components` в GitHub).
2. Настройте конфигурацию по примеру из файла `example.yaml`.
3. Скомпилируйте и прошейте устройство.

## Карта 22-байтного протокола UART
Основано на реверс-инжиниринге и дополнено в ходе тестирования на живой плате:

| Индекс | Назначение | Описание |
| :--- | :--- | :--- |
| `0` | Header | Всегда `0xAA` |
| `1` | Length | Всегда `0x14` (20 байт далее) |
| `2` | Type | `0x02` — команда от ESP, `0x01` — статус от AC / пинг |
| `3` | Power | `0x00` — выкл, `0x01` — вкл |
| `4` | Reserved | `0x00` |
| `5` | Vertical Swing | `0x00` — вкл, `0x06` — выкл |
| `6` | Command Type | `0x03` — изменение настроек, `0x0B` — опрос (`0x09`/`0x0A` в RX) |
| `7` | Mode | `0x00` Auto, `0x01` Cool, `0x02` Dry, `0x03` Heat, `0x04` Fan Only |
| `8` | Flags Bitmask | `0x10` — Display, `0x08` — Turbo, `0x04` — Quiet, `0x01` — Sleep |
| `9` | Fan Speed | `0x00` Auto, `0x01` Low, `0x02` Medium, `0x03` High |
| `10` | Target Temp | `0x10`–`0x20` (`16–32 °C`) |
| `11` | Horiz. Swing / Room Temp | В **TX**: `0x1C` выкл, `0x1D` вкл. В **RX**: текущая температура в °C (`0x9E` = обрыв датчика) |
| `12–16` | Reserved | `0x00` |
| `17–18` | Session ID | Случайная пара байт (генерируется при старте ESP) |
| `19` | Error Code | В **RX**: код ошибки (`0x00` — норма, `0x02` — `F6`, `0x1B` — `E1`) |
| `20` | Reserved | `0x00` |
| `21` | Checksum | Сумма байт `0..20` по маске `& 0xFF` |

**Пинг-пакет запроса статуса (раз в 30 сек):** `AA 02 01 AD`
